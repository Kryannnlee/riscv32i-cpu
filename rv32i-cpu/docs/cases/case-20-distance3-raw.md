# Case 20 · 隔 3 条的 RAW 读到了旧值，转发救不了

> **代码来源**：原始　**严重程度**：静默（程序继续跑，结果错）　**阶段**：指令集补齐

---

## 1. 现象

加完 `blt/bge/bltu/bgeu` 后跑流水线测试：

```
FAIL  x15 = 222   期望 111
```

程序逻辑（精简）：

```asm
addi x14, x0, -1     # x14 = 0xFFFFFFFF
blt  x13, x14, +8    # 1 < -1 ？否 -> 不跳
addi x15, x0, 111    # 应该执行
bltu x13, x14, +8    # 1 <u 0xFFFFFFFF ？是 -> 跳，跳过下面这条
addi x15, x0, 222    # 应该跳过
```

`x15` 应该是 111，实际 222 —— 说明 `bltu` **没有跳**。

单周期 CPU 跑同一程序 **全对**，所以 ALU 和分支判断逻辑没问题。

## 2. 定位过程

**第一步：探针看向量**

在 EX 级打印：

```
c52  pc=180 f3=110 alu_sel=6 rs2=14(=0) fwd_b=00 alu_res=00000000 taken=0
```

`bltu` 在 pc=180，ALU 确实做了 SLTU（`alu_sel=6`），但读到的 x14 是 **0**，
而 x14 应该是 `0xFFFFFFFF`。

**第二步：查寄存器堆**

另一个探针显示：x14 在 c51 确实被写成了 `0xFFFFFFFF`。

所以**寄存器里的值是对的，但读出来的是 0**。

**第三步：对时序**

```
第 42 条 addi x14 ：  EX(T)    MEM(T+1)   WB(T+2，时钟沿写入)
第 45 条 bltu    ：                      ID(T+2)   EX(T+3)
                                          ↑
                              这一拍读 x14，而写入就在同一拍末尾
```

**读和写在同一个周期**：

- 读是组合逻辑，这一拍内立刻返回
- 写是 `always_ff`，要等这一拍**结束**的时钟沿

所以读到的是写入之前的旧值。

**第四步：为什么转发也没用**

`bltu` 到 EX 时（T+3），第 42 条已经不在 MEM/WB 里了（它 T+2 就走了）。
转发只能从 EX/MEM 和 MEM/WB 拿，两者都没有它。

## 3. 这是哪一类冒险

按"隔几条"分类：

| 距离 | 生产者位置 | 现有手段 | 够吗 |
| --- | --- | --- | --- |
| 1 | EX/MEM | 转发 | ✅ |
| 2 | MEM/WB | 转发 | ✅ |
| **3** | **已在 WB，正写寄存器** | **转发已经来不及** | ❌ |
| 4 及以上 | 已写进寄存器堆 | 直接读 | ✅ |

**距离 3 是转发覆盖不到的盲区**——生产者和消费者的读写正好撞在同一拍。

## 4. 修法：寄存器堆的写优先旁路

```systemverilog
assign rs1_data = (rs1 == 5'd0) ? 32'd0 :
                  ((we && (rd == rs1)) ? wr_data : regs[rs1]);
assign rs2_data = (rs2 == 5'd0) ? 32'd0 :
                  ((we && (rd == rs2)) ? wr_data : regs[rs2]);
```

含义：**同一拍里既写 rd、又读同一个 rd，读口直接返回要写的值**，不等时钟沿。

MIPS/RISC-V 的标准做法（教材里叫 write-first / internal forwarding），
很多实现是靠"写在时钟前半拍、读在后半拍"实现同一个效果。
同步复位的 FPGA 设计里，用组合旁路更直接。

## 5. 为什么之前一直没暴露

之前的测试程序里，所有相关都是**距离 1 或 2**：

```
addi x1, x0, 5     # x1
add  x2, x1, x1    # 距离 1 -> EX/MEM 转发
addi x3, ...
add  x4, x2, x3    # x2 距离 2 -> MEM/WB 转发
```

**从没出现过"生产者刚好在 WB、消费者刚好在 ID"的情况。**

这次新加的分支测试，`addi x14` 和 `bltu` 之间隔了两条无关指令，正好凑成距离 3。

## 6. 怎么防止再犯

| 做法 | 说明 |
| --- | --- |
| **三种距离都要测** | 距离 1（转发 EX/MEM）、2（转发 MEM/WB）、3（写优先旁路） |
| 别假设"转发就够了" | 转发覆盖的是 1~2，距离 3 靠寄存器堆本身 |
| 写优先旁路要单测 | `regfile_tb` 里加一条："同拍写 rd、读 rd，读到的应该是新值" |

推荐的最小测试：

```asm
addi x1, x0, 11
addi x9, x0, 0      # 占位
addi x8, x0, 0      # 占位
add  x2, x1, x1     # 距离 3 读 x1，必须得到 11
```

## 7. 一句话记忆

> 转发能救"近的"，寄存器堆的写优先旁路救"远的"。
> **读写撞在同一拍**这件事，转发看不见。

## 补记：写优先旁路在单周期里形成组合环

加完旁路后，流水线全过，但**单周期 `cpu_tb` 直接卡死**（仿真跑几分钟不结束）。

原因：单周期里 `wr_data` 直接来自**当拍的 ALU 结果**，于是绕成环：

```
alu_result → wb_data → regfile 旁路 → rs1_data → alu_a → alu_result
     ↑                                                      |
     └──────────────────────────────────────────────────────┘
```

流水线里 `wr_data` 来自 `mem_wb` 寄存器，环被寄存器打断，所以那边没问题。

**修法**：给 `regfile` 加参数 `BYPASS`，单周期例化时关掉。

```systemverilog
module regfile #(parameter bit BYPASS = 1) (...);
assign rs1_data = (rs1 == 0) ? 0 :
                  ((BYPASS && we && rd == rs1) ? wr_data : regs[rs1]);
```

```systemverilog
regfile #(.BYPASS(0)) register_file ( ... );   // cpu_top
```

**教训**：组合逻辑的旁路，一定要检查"这条路径是否会和别的路径绕成一个环"。
单周期和流水线的拓扑不同，同一个模块在两边的合法性可能相反。
