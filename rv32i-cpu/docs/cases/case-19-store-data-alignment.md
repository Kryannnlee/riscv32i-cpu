# Case 19 · `sb` 写第二个字节时取错了数据源

> **代码来源**：原始　**严重程度**：静默（程序继续跑，但内存内容错）　**阶段**：字节访存

---

## 1. 现象

加完 `sb/sh/lb/lh` 之后跑流水线测试：

```
  FAIL   x26 = 35   期望 291
```

`x26` 应该是 `0x123` = 291，实际是 `0x23` = 35——**只有最低字节写进去了，第二个字节没生效**。

## 2. 当时的代码

`dmem.sv` 按字节通道复制：

```systemverilog
if (be[0]) mem[addr[31:2]][7:0]   <= wr_data[7:0];
if (be[1]) mem[addr[31:2]][15:8]  <= wr_data[15:8];    // <-- 错
if (be[2]) mem[addr[31:2]][23:16] <= wr_data[23:16];
if (be[3]) mem[addr[31:2]][31:24] <= wr_data[31:24];
```

测试程序：

```asm
addi x25, x0, 0x23
sb   x25, 20(x0)     # 写 byte20 = 0x23
addi x25, x0, 0x01
sb   x25, 21(x0)     # 写 byte21 = 0x01
lw   x26, 20(x0)     # 期望 0x00000123
```

## 3. 为什么错

**RISC-V 规定：`sb` 存的是 `rs2` 的低 8 位，无论写到哪个字节位置。**

所以 `sb x25, 21(x0)` 应该把 `x25[7:0] = 0x01` 写到 byte21。
但代码取的是 `wr_data[15:8]`，而 `x25 = 0x00000001`，`wr_data[15:8]` 是 **0x00**。

结果 byte21 被写成 0x00，整字读回来就是 `0x00000023`。

## 4. 怎么定位的

反推：`0x123` 变成 `0x23`，说明**高位字节被写成了 0**，而不是"没写"。
如果完全没写，`lw` 会因为 byte22/23 未初始化而得到 X（这个也遇到了，见 case-17 补记）。
得到的是干净的大端错位，说明第二个 `sb` 确实执行了，只是数据源选错。

于是去查 `sb` 时数据从哪来——问题出在按字节通道复制时用了 `wr_data[15:8]`。

## 5. 修法：先把数据"摊"到对应通道

在 MEM 级加一步对齐，`dmem` 保持"按通道复制"的简单结构：

```systemverilog
always_comb begin
    case (ex_mem_funct3)
        3'b000:  store_data = {4{ex_mem_rs2[7:0]}};                 // sb：4 个通道都放低字节
        3'b001:  store_data = ex_mem_alu_result[1]
                             ? {ex_mem_rs2[15:0], 16'd0}            // sh 写高半字
                             : {16'd0, ex_mem_rs2[15:0]};           // sh 写低半字
        default: store_data = ex_mem_rs2;                           // sw
    endcase
end
```

修完 `x26 = 0x123`。

## 6. 怎么防止再犯

| 要点 | 说明 |
| --- | --- |
| 存储数据的来源永远是 rs2 **低位** | 与地址无关，地址只决定"放到哪" |
| 把"放到哪"和"放什么"分开 | 字节使能管位置，数据对齐管内容，两者独立 |
| 测试要覆盖**每个字节位置** | 只测 byte0 的话这个 bug 完全看不出来 |

推荐的最小测试集：

```asm
sb 到地址 20、21、22、23 各一次，然后 lw 读回，检查 4 个字节都对
sh 到 addr[1]=0 和 addr[1]=1 各一次
```

## 7. 一句话记忆

> **写内存时：数据永远取低位，地址只决定放哪。**
> 按字节通道复制之前，必须先把数据摊到对应通道上。
