# Case 21 · UART 的 tx 做成寄存器输出，起始位多一拍

> **代码来源**：原始　**严重程度**：静默（波形看着"像对的"，但接收端会错）　**阶段**：UART

---

## 1. 现象

`uart_tx` 写完，testbench 把串行流解码回字节：

```
FAIL 发送 55 -> 收到 d5
FAIL 发送 a3 -> 收到 f4
```

发的和收的不一样，但波形上看"起始位、数据、停止位都有"，很像没问题。

## 2. 定位：量每一位的实际宽度

写个探针，打印 `tx` 每次翻转的时钟数：

```
cyc=5   tx 1 -> 0     ← 起始位开始
cyc=16  tx 0 -> 1     ← 11 拍！
cyc=26  10 拍
cyc=36  10 拍
```

**起始位 11 拍，其余 10 拍。** 差这一拍，接收端采样点逐位漂移，最后一位采到停止位上。

## 3. 原因

`tx` 和 `state` 都是寄存器：

```systemverilog
always_ff @(posedge clk) begin
    case (state)
        IDLE: if (send_pulse) tx <= 1'b0;   // 已在 IDLE 拉低
        START: tx <= 1'b0;                  // START 又维持一整拍
```

`tx` 比 `state` 晚一拍变化，而 IDLE 里又提前拉低了一次，起始位就多了一拍。

## 4. 修法：tx 改成组合输出

```systemverilog
always_comb begin
    case (state)
        IDLE:    tx = 1'b1;
        START:   tx = 1'b0;
        DATA:    tx = data_reg[bit_cnt];
        STOP:    tx = 1'b1;
        default: tx = 1'b1;
    endcase
end
```

物理含义更清楚：**tx 是"当前状态"的函数，不是"上一拍状态"的函数。**
改完每位严格 10 拍，5 个测试字节全过。

## 5. 顺手记两个 testbench 的坑

| 坑 | 现象 | 原因 |
| --- | --- | --- |
| 采样组合信号不加延迟 | 读到的总是上一位的值 | 时钟沿后组合逻辑要过 delta 才稳定，`@(posedge clk)` 后立刻读是旧的 |
| 用 `@(negedge tx)` 等电平 | 全 1 的字节直接卡死 | 如果 tx 已经是低，再等下降沿永远等不到 |

正确写法：

```systemverilog
while (tx !== 1'b0) @(posedge clk);   // 等电平，不用等边沿
#1;                                    // 采样前让组合逻辑稳定
```

## 6. 怎么防止再犯

- **寄存器输出 = 晚一拍**。凡是"输出要跟状态同拍变化"的地方，用 `always_comb`。
- 串口这类**靠时间对齐**的协议，一定要量实际位宽，不能靠看波形"像不像"。
- testbench 采样时刻要留余量：`#1` 或采在位的正中间。

## 7. 一句话记忆

> 输出用寄存器还是组合，决定了它比状态**早一拍还是晚一拍**。
> 串口差一拍，整帧就废了。
