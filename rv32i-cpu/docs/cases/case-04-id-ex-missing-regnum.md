# Case 04 · `id_ex` 只存了数据，没存寄存器编号，转发根本无法比较

> **代码来源**：原始　**严重程度**：阻塞（写不下去，不是跑错）　**阶段**：6b 开头

---

## 1. 现象

准备写转发单元时发现：手上只有 `rs1_data` / `rs2_data`（数据），
但转发要做的是"**这条指令要读的寄存器号** == **上一条要写的寄存器号**吗"。

编号根本没有带进 EX 级。写不下去。

## 2. 当时的代码

`id_ex.sv` 的端口：

```systemverilog
    // ── 数据（ID 产出）──
    input  logic [31:0] rs1_data_in,
    input  logic [31:0] rs2_data_in,
    input  logic [31:0] imm_in,
    input  logic [4:0]  rd_in,
    ...
```

有 `rd`（目的寄存器号），但没有 `rs1` / `rs2`（源寄存器号）。

## 3. 为什么错

ID 级对外"产出"的是**数据**，因为它已经从寄存器堆读出来了。
但寄存器号是另一回事——转发单元需要的不是数据，是"编号"这个身份信息。

只有 `rd` 被存下来，是因为 WB 级写回时需要知道写哪个；
而 `rs1`/`rs2` 在 ID 级读完就"用完"了，当时没觉得后面还要用。

**这是典型的"字段没想全"**：定流水线寄存器字段时，只考虑了当前这一级的需求，
没考虑后面的级还要不要这个信息。

## 4. 怎么定位的

按工作循环走到"定接口"这一步，把转发单元的输入列出来：

```
需要：EX 指令要读的两个编号、上一条的 rd、上上条的 rd
实际有：rs1_data、rs2_data、rd（EX 级的 rd 有，源的编号没有）
```

一列就发现缺口。

## 5. 修正后的代码

`id_ex.sv` 增加两对端口：

```systemverilog
    // 寄存器编号：转发单元要拿它跟上游的 rd 比，光有数据不够
    input  logic [4:0]  rs1_in,
    input  logic [4:0]  rs2_in,
    ...
    output logic [4:0]  rs1_out,
    output logic [4:0]  rs2_out,
```

`cpu_pipe.sv` 接上：

```systemverilog
        .rs1_in(if_id_instr[19:15]), .rs2_in(if_id_instr[24:20]),
        ...
        .rs1_out(id_ex_rs1), .rs2_out(id_ex_rs2),
```

## 6. 怎么防止再犯

**定流水线寄存器字段时，多问一句：后面哪一级还要用这个？**

`01-architecture.md` 第 8 节那张"各流水线寄存器存什么"的表，就是干这个用的。
表里每加一行，都要能说出"谁用它"。

## 7. 一句话记忆

> `id_ex` 存的不是"ID 用剩的东西"，是"ID 产出、后面还要用的一切"。
> 数据和编号是两样东西，都要存。
