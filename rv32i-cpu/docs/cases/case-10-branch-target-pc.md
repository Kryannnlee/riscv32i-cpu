# Case 10 · 分支目标用当前 `pc` 算，跳飞 8 字节

> **代码来源**：原始（讨论中对比的两种写法）　**严重程度**：致命
> **实际影响**：**写码前就识别并避开**，没有造成故障　**阶段**：6d

---

## 1. 现象（假如踩了会怎样）

分支明明该跳，跳完却跑到一段莫名其妙的地址，
或者执行了几个字节偏移之后的指令——**跳是跳了，但跳歪了**。

因为是"接近正确"的地址，不是完全乱飞，所以特别难查。

## 2. 错误写法

```systemverilog
    assign next_pc = branch_taken ? (pc + imm) : pc_plus4;
                                   ^^^^^^^^^
                                   错在这里
```

## 3. 为什么错

分支在 **EX 级**判断。那一刻，`pc` 寄存器已经跑到哪了？

```
        C1   C2   C3   C4
分支     IF   ID   EX   MEM
I+1           IF   ID   EX
I+2                IF   ID
        ↑          ↑
        pc=分支     pc=分支+8  ← 分支在 EX 这一刻，pc 指向这里
```

**分支在 EX 时，`pc` 已经指向它后面第 2 条。**

用 `pc + imm` 算目标，等于多加了 `2 × 4 = 8` 字节。

正确的做法是用**这条分支自己的地址**——它在 ID 级被锁进 `id_ex_pc`，一路带到了 EX。

## 4. 怎么想到的

画上面那张表，然后问：**"分支进 EX 的那一刻，`pc` 的值是什么？"**

答案不是"分支的地址"，是"分支后面第 2 条的地址"。

流水线里"当前 pc"和"这条指令的 pc"是两个不同的东西。

## 5. 正确写法

```systemverilog
    // 目标地址 = 分支自己的 PC + B 型立即数
    assign branch_target = id_ex_pc + id_ex_imm;

    assign next_pc = pc_redirect ? branch_target : pc_plus4;
```

`id_ex_pc` 就是这条分支在 ID 级时被锁存下来的自己的地址。

## 6. 怎么防止再犯

在流水线里用 `pc` 之前，**先确认它此刻指向哪一条**。

经验值：

| 谁在用 pc | 此刻 pc 指向 |
| --- | --- |
| IF 级 | 正在取的这条 |
| ID 级 | 后 1 条 |
| EX 级 | 后 2 条（含正在取的） |
| MEM 级 | 后 3 条 |

所以 EX/MEM 之后还要用"自己的 PC"时，必须用流水线寄存器里存的那份。

## 7. 一句话记忆

> 流水线里 `pc` 是"别人的地址"。要用"我自己的地址"，去 `id_ex_pc` 拿。
