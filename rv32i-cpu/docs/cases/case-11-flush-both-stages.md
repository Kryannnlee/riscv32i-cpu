# Case 11 · flush 只清 `if_id` 不清 `id_ex`，毒药指令照样执行

> **代码来源**：原始　**严重程度**：静默（结果错，但不崩）
> **实际影响**：正常写码时是正确的；**通过"故意断掉 flush"的实验复现过后果**　**阶段**：6d

---

## 1. 现象

分支跳转之后，**被跳过的那些指令仍然执行了一次**，
把寄存器写成了不该有的值。

比如分支跳过了 `addi x11, x0, 222`，最后 `x11` 却变成了 222。

## 2. 错误写法

```systemverilog
    if_id if_id_i (
        ...
        .flush(pc_redirect),          // 只清了 ID/EX 之前那一级
        ...
    );

    id_ex id_ex_i (
        ...
        .flush(stall),                // ← 只有 load-use 才清，分支不清
        ...
    );
```

## 3. 为什么错

分支在 EX 级判断时，取错的指令有**两条**，分别躺在两个不同的寄存器里：

```
        C1   C2   C3   C4
分支     IF   ID   EX
I+1           IF   ID    ← 躺在 if_id 里
I+2                IF    ← 正在取，一拍后进 if_id
```

- `if_id` 里的 I+1（ID 级）是错的 → 清 `if_id`
- `id_ex` 在下一拍会把 I+1 接进来（或把 I+2 接进来），也会变成错的指令 → 也要清

如果只清 `if_id`，`id_ex` 下一个时钟沿仍然会从（已经清空的）`if_id` 拿数据…
等等，这里有个细节：`if_id` 被清空后输出是 0，`id_ex` 接到的就是 0，看起来"自动"清了。

**但时序上会漏一拍。** 清 `if_id` 的那个沿，`id_ex` 同时也在采样**清之前**的 `if_id` 值——
也就是说 I+1 正好在这一拍被送进 EX 执行了。

## 4. 怎么验证的（这个方法值得学）

不做"读代码猜"，直接做**破坏性实验**：

把 flush 断掉：

```systemverilog
        .flush(1'b0),          // if_id 不冲刷
        .flush(stall),         // id_ex 只有 load-use 才清
```

重跑，结果：

```
  FAIL   x11 = 222   期望 3
  FAIL   跳转次数 = 3，期望 2
```

`x11` 变成了 222 —— 正是那条本该被跳过的毒药指令写进去的。
`redirect_count` 也从 2 变成 3，说明跳转后又多跳了一次。

**测试确实能抓到这个问题。** 恢复 `.flush(pc_redirect)` 后回到全绿。

## 5. 正确写法

```systemverilog
    if_id if_id_i (
        ... .stall(stall), .flush(pc_redirect), ...
    );

    id_ex id_ex_i (
        ... .flush(stall | pc_redirect), ...
    );
```

**两个都要清**，而且 `id_ex` 的 flush 要把 load-use 和分支两种情况**或**起来。

## 6. 怎么防止再犯

- 问自己："取错的指令此刻躺在哪些流水线寄存器里？" —— 有几个就清几个。
- 用**毒药指令**做测试：分支后面放一条写特殊值的指令，跑完检查那个寄存器没被改动。
- 关键测试要做**反向验证**：故意把机制断掉，确认测试会红。只会绿的测试没有意义。

## 7. 一句话记忆

> 冲刷不是"清一个寄存器"，是"清掉所有装着错指令的寄存器"。
> 改完一定要故意断掉验证一次。
