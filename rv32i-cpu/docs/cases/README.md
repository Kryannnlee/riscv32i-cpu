# 踩坑档案（cases）

> 这里存放项目里**真正踩过**的坑，一个坑一个文件。
> 和 `09-pitfalls.md` 的区别：那里是"避坑清单"（含未踩到的防范条目），
> 这里是**事故档案**——当时到底发生了什么、代码长什么样、怎么定位的。

---

## 为什么要单独建这个

`09-pitfalls.md` 只有一句话结论，看完记不住。

真正能救命的是**当时的现场**：错误代码长什么样、报错是什么、你是怎么一步步找到的。
写完论文复盘、面试讲项目、或者过半年又犯同样的错时，看这个比看结论有用。

---

## 每条档案的固定结构

```
1. 现象        —— 屏幕上看到了什么，越具体越好
2. 当时的代码  —— 错误版本原样贴出来
3. 为什么错    —— 硬件/语言层面的原因
4. 怎么定位的  —— 从现象走到根因的路径
5. 修正后的代码
6. 怎么防止再犯
7. 一句话记忆  —— 能背下来的一句
```

每条开头标注：
- **代码来源**：`原始`（当时真实的代码）/ `重建`（根据记录复原，细节可能不完全一致）
- **严重程度**：`致命`（功能全错）/ `静默`（能跑但结果错）/ `浪费`（只是慢或报错）

## 怎么用这个档案

**写论文/面试时**：第 2、4、7 节是素材——"我遇到了什么问题、怎么定位的、学到了什么"，
比"我实现了转发"有价值得多。

**又踩到类似的坑时**：先按"一句话记忆"扫一遍，多半能直接对上。

**新踩到坑时**：照上面的结构补一条，编号顺延，并在索引表加一行。
