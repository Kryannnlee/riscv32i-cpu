# Case 22 · 拿静态指令条数当 CPI 分母，算出"负的开销"

> **代码来源**：原始　**严重程度**：静默（功能全对，性能结论是错的）　**阶段**：性能评估

---

## 1. 现象

`cpu_pipe_tb` 跑完，性能那一栏打印：

```
  其中：load-use 停顿 1 拍，改道 7 次
  无冒险理想 = 57 + 4(填充) = 61 拍（CPI 1.070），开销 -12 拍
```

**开销是负数。** 实测跑完比"理想"还快 12 拍——这在流水线里不可能。

更早的版本（41 条程序）显示 49 拍，按公式算是 54 拍，于是当时写下一条结论：

> 简单加法模型不成立……性能数据必须实测，不能靠公式推。（`progress.md` [033]）

## 2. 当时的代码

```systemverilog
localparam int PROG_LEN = 57;        // imem 里写了多少条

// "程序跑完"的时刻 = x30 写回
if (cyc_done == 0 && dut.mem_wb_reg_write && dut.mem_wb_rd == 5'd30)
    cyc_done = cycles;

开销 = cyc_done - (PROG_LEN + 4);
```

## 3. 为什么错：两个独立的错叠在一起

**错 1：完成标记早就过期了。**

x30 是 `mem[40]` 的 `lhu` 写的。程序从 41 条扩到 57 条之后，
`mem[40]` 只是**程序中间**，后面还有 mem[41..56]。
所以 `cyc_done = 49` 测的是"跑到一半"的时刻，不是程序结束。

**错 2：`PROG_LEN` 是静态条数，CPI 要的是动态条数。**

imem 里写了 57 条，但有 7 处跳转，共跳过 8 条：

| 跳转 | 落点 | 被跳过 |
| --- | --- | --- |
| `beq  @11` | mem[13] | mem[12] |
| `bne  @13` | mem[15] | mem[14] |
| `jal  @18` | mem[21] | mem[19] mem[20] |
| `jalr @24` | mem[26] | mem[25] |
| `bltu @45` | mem[47] | mem[46] |
| `bge  @51` | mem[53] | mem[52] |
| `bgeu @54` | mem[56] | mem[55] |

**实际执行 57 - 8 = 49 条。** 分母应该是 49。

## 4. 怎么定位的：拿老数据反推

关键一步是**回头验算上一版**。41 条的那版程序：

```
imem 写了 41 条 → 跳过 5 条 → 实际执行 36 条
预测 = 36(执行) + 4(填充) + 1(停顿) + 4x2(改道) = 49 拍
实测 = 49 拍                       ← 分毫不差
```

模型**从来就是准的**，[033] 那条"模型不成立"是拿 41 当分母推出来的假象。

改完分母 + 改完完成标记后，当前程序：

```
预测 = 49 + 4 + 1 + 7x2 = 68 拍
实测 = 68 拍                       ← 一致
```

## 5. 修正后的代码

```systemverilog
// 静态条数（imem 里写了多少）和动态条数（真正执行了多少）分开写
localparam int PROG_WORDS   = 57;
localparam int PROG_RETIRED = 49;   // 57 - 8 条被跳过的

// 完成标记换成真正的最后一条：mem[56] addi x18, x0, 888
if (cyc_done == 0 && dut.mem_wb_reg_write && dut.mem_wb_rd == 5'd18)
    cyc_done = cycles;

// 预测与实测必须相等，不相等就报错（不再只是打印）
predicted = PROG_RETIRED + 4 + stall_count + 2 * redirect_count;
if (cyc_done != predicted) begin
    $display("  FAIL   实测 %0d 拍，公式预测 %0d 拍", cyc_done, predicted);
    errors++;
end
```

CPI 从错误的 0.860（49/57）变成 **68/49 = 1.388**。

## 6. 怎么防止再犯

- **imem 里写了几条 ≠ 程序执行了几条。** 只要有跳转，两者就不相等。
- **性能公式要写成断言，不能只打印。** 打印出来没人看，断言一错就红。
  这次就是"模型 vs 实测"两边对不上，才把分母错误揪出来。
- **表里同时写出两个数**（静态 / 动态），差异一眼可见，不会再次混淆。
- **改程序长度时，所有"最后一条指令"的假设都要重新检查。**
  完成标记、断言长度、循环次数，全是耦合点。

## 7. 一句话记忆

> 有跳转的程序，imem 里有几条不等于跑了几条。
> CPI 的分母永远是**退役（retire）条数**，不是源代码行数。
