# Case 02 · 忘例化 imm_gen，`imm` 悬空成 X，整条流水线结果全错

> **代码来源**：重建（据此前进度记录复原，细节可能与当时略有出入）
> **严重程度**：致命　**阶段**：5（cpu_pipe 整合）

---

## 1. 现象

五级流水线整合完第一次跑，`cpu_pipe_tb` 出来的寄存器值全是 `x`：

```
x1=x (期望 5)
x2=x (期望 3)
x3=x (期望 8)
x4=x (期望 2)
```

注意不是"算错了"，而是 `x`。**只要看到 X，就说明有信号从来没被驱动过。**

## 2. 当时的代码

`cpu_pipe.sv` 的 ID 段，只接了 decoder、regfile、id_ex：

```systemverilog
    decoder decoder_i ( ... );

    regfile regfile_i ( ... );

    id_ex id_ex_i (
        ...
        .imm_in(imm),        // ← imm 从来没被赋过值
        ...
    );
    // 少了 imm_gen 的例化
```

`imm` 在文件顶上声明了：

```systemverilog
    logic [31:0] rs1_data, rs2_data, imm;
```

声明了但不驱动 → 高阻 Z → 送进 `id_ex` 变 X → 一路传到 ALU → 全 X。

## 3. 为什么错

**声明一个信号 ≠ 给它接上电路。**

Verilog 里 `logic [31:0] imm;` 只是命名了一根线。如果没有任何 `assign` 或模块输出驱动它，
仿真里它就是 `z`；`z` 进到寄存器或算术运算里就变成 `x`；`x` 有传染性，会污染整条数据通路。

## 4. 怎么定位的

定位路径（这个套路值得记）：

1. 看到结果是 `x` 而不是错误数值 → 先怀疑**未驱动信号**
2. 打开波形，从输出往回追：`x4` 是 X → 看 ALU 的 `a`/`b` → `b` 是 X → 看 `alu_b` → `imm` 是 X
3. 再看 `imm` 由谁驱动 → 全模块搜 `imm` → 发现只有声明和端口连接，**没有任何驱动源**
4. 回到架构图对照：ID 级应该有 decoder + regfile + imm_gen 三个模块，代码里只有两个

## 5. 修正后的代码

```systemverilog
    // 立即数生成
    imm_gen imm_gen_i (
        .instr (if_id_instr),
        .imm   (imm)
    );
```

## 6. 怎么防止再犯

- **按架构图逐级核对**：每个阶段该有哪几个模块，例化完打勾。少一个模块不会报错，只会表现为 X。
- **X 是最有价值的调试信号**：`z`/`x` 几乎总是指向"没人驱动"或"没复位"。
- 集成时先把每个 stage 的模块列成清单，再逐个接。

## 7. 一句话记忆

> 结果是 `x` 不是"算错了"，是"这根线压根没人管"。往回找那个没被驱动的信号。
