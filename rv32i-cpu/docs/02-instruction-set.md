# 02 · 指令编码速查（可对答案）

> 用途：写 decoder / imm_gen 时，拿这里对答案。
> 只列**本项目子集**，不是全部 RV32I。位编号从 31（最高位）到 0（最低位）。

---

## 字段

| 字段 | 含义 | 位 |
| --- | --- | --- |
| opcode | 操作码，**最低 7 位** | [6:0] |
| rd | 目标寄存器编号 | 随格式 |
| funct3 | 进一步区分 | [14:12] |
| rs1 | 源寄存器 1 | [19:15] |
| rs2 | 源寄存器 2 | [24:20] |
| funct7 | R 型再区分 | [31:25] |
| imm | 立即数 | 随格式 |

---

## 字段含义注解（随问随加）

### rs1 / rs2 —— 源寄存器（register source）
- 5 位编号（0~31），指出"**从哪个寄存器读操作数**"。
- rs1 = 第一个源，rs2 = 第二个源。有的指令只用 rs1（如 ADDI、LW）。

### rd —— 目标寄存器（register destination）
- 5 位编号，指出"**结果写回哪个寄存器**"。
- **S、B 型没有 rd**（它们不写寄存器）。

### opcode —— 主操作码
- **最低 7 位**，表示**指令大类**（R / I立即数 / Load / Store / Branch / JAL / JALR / LUI / AUIPC）。
- 译码时**先看它**。

### funct3 / funct7 —— 功能码（辅助操作码）
- 同一个 opcode 下再细分指令（如 ADD vs SUB）。
- **为什么是 3 和 7 位？不是随便定的，是布局算出来的**：
  - 固定字段占：`opcode 7 + rd 5 + funct3 3 + rs1 5 + rs2 5 = 25 位`，**剩 7 位** → 正好是 funct7 的位置。
  - funct3 就是夹在 rs1 和 rd 之间的 **[14:12] 那 3 位**。
  - 容量：funct3 = 2³ = 8 种；funct7 = 2⁷ = 128 种，够细分。
- ⚠️ **funct3 的含义依赖 opcode**：同样是 `000`，在 R 型是 ADD，在 I 型是 ADDI，在 B 型是 BEQ。

### imm —— 立即数（为什么有的被拆开）
- 因为格式要求 `rs1/rs2/rd/funct3` **固定在同样位置**（便于译码）→ 立即数只能塞进**剩下的位**。
  - **I 型**：剩下的正好是连续的 12 位 `[31:20]` → **不拆**。
  - **U 型**：没有 rs1/rs2，立即数占 `[31:12]` 一整段 → **不拆**。
  - **S / B / J 型**：寄存器字段**插在中间**，把立即数**切断** → **拆成几段**。
  - B / J 还要**丢掉 bit0**（恒 0，偏移是 2 字节对齐）。

## 六种格式布局

**R 型**（ADD SUB AND OR XOR SLT）
```

┌───────────┬────────┬────────┬───────┬──────┬────────┐
│  funct7   │  rs2   │  rs1   │funct3 │  rd  │ opcode │
└───────────┴────────┴────────┴───────┴──────┴────────┘
```

**I 型**（ADDI ANDI ORI XORI SLTI / LW / JALR）
```
31                    20 19    15 14  12 11   7 6      0
┌────────────────────────┬────────┬───────┬──────┬────────┐
│       imm[11:0]        │  rs1   │funct3 │  rd  │ opcode │
└────────────────────────┴────────┴───────┴──────┴────────┘
```

**S 型**（SW）
```
31        25 24    20 19    15 14  12 11   7 6      0
┌───────────┬────────┬────────┬───────┬──────────┬────────┐

└───────────┴────────┴────────┴───────┴──────────┴────────┘
```

**B 型**（BEQ BNE）
```

│ imm[12|   │  rs2   │  rs1   │funct3 │imm[4:1|│imm│ opcode │

```

```

```


## 六种格式逐个详解

**设计三原则**（理解格式的钥匙）：
1. `opcode` 固定在**最低 7 位** → 先看它知道格式。
2. `rd/rs1/rs2/funct3` 尽量放**固定位置** → 译码器简单,取寄存器字段不用管格式。
3. 立即数只能塞进**剩下的位** → S/B/J 的立即数因此被拆散;分支/跳转偏移是 **2 的倍数**,所以 **bit0 永远是 0,不存**。

**推论：每个字段一旦出现，位置就固定：**

| 字段 | 出现在哪些格式 | 位置 |
| --- | --- | --- |
| opcode | **全部** | [6:0] |
| rd | R / I / U / J | [11:7] |
| funct3 | R / I / S / B | [14:12] |
| rs1 | R / I / S / B | [19:15] |
| rs2 | R / S / B | [24:20] |
| funct7 | 只有 R | [31:25] |

**一句话**：先定死"寄存器/funct3 字段"的位置（为译码简单）→ 立即数只能填剩下的缝 → 缝不连续（S/B/J）就被拆开。

### R 型 —— 寄存器-寄存器
- **用途**（两个操作数都来自寄存器，**无立即数**，结果写 rd）：
  - `ADD` = rs1 + rs2
  - `SUB` = rs1 − rs2
  - `AND` = rs1 & rs2（按位与）
  - `OR`  = rs1 \| rs2（按位或）
  - `XOR` = rs1 ^ rs2（按位异或）
  - `SLT` = (rs1 < rs2) ? 1 : 0（**有符号**比较）
- 例：`add x5,x6,x7` = `0x007302B3`

### I 型 —— 寄存器 + 立即数
- **用途**（读 rs1 和 imm，结果写 rd）：
  - `ADDI` = rs1 + imm
  - `ANDI` = rs1 & imm
  - `ORI`  = rs1 \| imm
  - `XORI` = rs1 ^ imm
  - `SLTI` = (rs1 < imm) ? 1 : 0（**有符号**）
  - `LW`   = 内存[rs1 + imm] → rd（读 4 字节）
  - `JALR` = rd ← PC+4；PC ← rs1 + imm（跳到寄存器地址）
- 立即数**一整段**在 `instr[31:20]`（12 位），**符号扩展**。
- 例：`addi x5,x6,10` = `0x00A30293`

### S 型 —— 写内存 STORE
- **用途**（**不写 rd**）：`SW` = 内存[rs1 + imm] ← rs2
- 立即数**拆两段**：高 7 位 `instr[31:25]`、低 5 位 `instr[11:7]`（给 `rs1/rs2/funct3` 让位）。
- 拼回：`{instr[31:25], instr[11:7]}`，符号扩展。
- 例：`sw x5,8(x6)` = `0x00532423`

### B 型 —— 条件分支
- **用途**（**不写 rd**）：
  - `BEQ` = 若 rs1 == rs2 → PC ← PC + imm
  - `BNE` = 若 rs1 != rs2 → PC ← PC + imm
- 立即数**拆得最散**（绕开所有寄存器字段），且 bit0=0。
- 拼回：`{instr[31], instr[7], instr[30:25], instr[11:8], 1'b0}`，符号扩展。
- 例：`beq x5,x6,8` = `0x00628463`

### U 型 —— 高位立即数
- **用途**（结果写 rd）：
  - `LUI`   = imm20 << 12（把高 20 位放进 rd）
  - `AUIPC` = PC + (imm20 << 12)（PC 相对地址）
- 立即数放**高 20 位** `instr[31:12]`，低 12 位补 0。
- 例：`lui x5,0x12345` = `0x123452B7`

### J 型 —— 无条件跳转
- **用途**（结果写 rd）：`JAL` = rd ← PC+4；PC ← PC + imm
- 立即数同样拆散，bit0=0。
- 拼回：`{instr[31], instr[19:12], instr[20], instr[30:21], 1'b0}`，符号扩展。
- 例：`jal x1,8` = `0x008000EF`

**记忆诀**：R 最简单(无立即数);I 立即数一整段;S/B/J 因让位给寄存器字段而被拆散;**U 型是"高 20 位"**。

## opcode 表（本项目用到的）

> `opcode = instr[6:0]`（最低 7 位）。译码**第一步**就是拿它和下面这些值比对，确定格式/大类。

| opcode[6:0] | 十六进制 | 格式 | 本项目包含的指令 | 说明 |
| --- | --- | --- | --- | --- |
| `0110011` | 0x33 | R | ADD SUB AND OR XOR SLT | 两个寄存器运算，**写 rd** |
| `0010011` | 0x13 | I | ADDI ANDI ORI XORI SLTI | 寄存器 + 立即数运算，**写 rd** |
| `0000011` | 0x03 | I(load) | LW | 读内存 → **写 rd** |
| `1100111` | 0x67 | I(jalr) | JALR | 跳到 `rs1+imm`，**写 rd**（返回地址） |
| `0100011` | 0x23 | S | SW | 寄存器 → 内存，**不写 rd** |
| `1100011` | 0x63 | B | BEQ BNE | 条件跳转，**不写 rd** |
| `0110111` | 0x37 | U | LUI | 高 20 位 → **写 rd** |
| `0010111` | 0x17 | U | AUIPC | PC + 高 20 位 → **写 rd** |
| `1101111` | 0x6F | J | JAL | 跳转并保存返回地址 → **写 rd** |

**怎么用（译码两步走）**：
1. **先看 `instr[6:0]`** → 落在上面哪一行 → 知道是哪种格式、属于哪一大类。
2. **再结合 `funct3` / `funct7`** → 在同一 opcode 下区分**具体是哪条**指令。
   - 例：`opcode=0x33` 且 `funct3=000`：还要看 `funct7`——`0000000`→ADD，`0100000`→SUB。

**小知识**：32 位指令的最低 2 位 `inst[1:0]` 恒为 `11`（表示这是一条 32 位指令），所以真正的 opcode 实际上是最低 7 位。
