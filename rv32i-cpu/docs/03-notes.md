## 第 1 轮：最顶层的模型

**Q1. CPU 是干什么的？**
- 学员答：Central Processor Unit，处理数据。
- **修正**：全称是 Central **Processing** Unit。更准确：CPU 按程序（一串指令）一条条执行，对数据进行**运算、搬运、控制**。核心是“执行指令”。
- ✅ 结论：**CPU = 执行指令的机器**。

**Q2. 一条指令执行的步骤？**
- 学员答：读寄存器 → 执行（漏了取指、译码、写回）。
- **正确顺序**：
```
取指 IF → 译码 ID → 执行 EX → 访存 MEM → 写回 WB
```
- ✅ 结论：**指令不是凭空出现的，要先用 PC 从内存取出来。**
- ️⚠️ 漏洞：默认“指令已经在那儿了”。

**Q3. CPU 里哪些是需要“记住”的（状态）？**
- 学员答：不确定。
- ✅ 结论：**状态 = 在时钟沿之间保持不变、供后续使用的值。**
  本项目里的状态：**PC、寄存器堆、流水线寄存器、内存**。
  共同点：不会因输入变化立刻变，而是“等时钟沿才更新”。

**Q4. 为什么需要时钟？**
- 学员答：时序逻辑需要；频率影响性能。
- **精确说法**：时钟给“状态更新”一个**统一节拍**，决定**什么时候把新值锁进寄存器**。
- ✅ 补充：性能 = **频率 × IPC**（每拍执行多少条）。只提频率不完整。
- ️⚠️ 漏洞：频率高 ≠ 一定快。

**Q5. 组合逻辑 vs 时序逻辑？**
- 学员答：组合=编码器/译码器；时序=计数器/寄存器。
- **小修正**：时序逻辑的关键不是“跟时间有关”，而是**输出依赖“过去的状态（记忆）”**；记忆靠时钟沿更新。
- ✅ 结论：
  - 组合逻辑：输出**只**由当前输入决定（ALU、MUX、译码器）。
  - 时序逻辑：输出由当前输入 **+ 过去状态**决定（PC、寄存器堆、计数器）。

## 第 2 轮：指令、状态与结构

> 本轮学员多数“不知道”，属于正常——这些是**该学什么**的探针；下面为讲解。

**Q1. 指令存在哪？CPU 靠什么找下一条？**
- ✅ 指令存在**内存（指令内存）**；CPU 用 **PC（程序计数器）**存“下一条指令的地址”，取指时用 PC 去内存取指令，执行完 PC 指向下一条（通常 +4）。← 取指 IF。

**Q2. 怎么知道是加法还是跳转？**
- ✅ 指令是 32 位，**最低 7 位 = opcode（操作码）**；**译码器**根据 opcode/funct3/funct7 判断指令并产出控制信号。← 译码 ID。

**Q3. 寄存器堆 vs 内存？**
- 学员答对：寄存器最快，全用内存会慢。
- ✅ **存储层次**：寄存器 → Cache → 内存。寄存器堆在 CPU 内，小（32 个）而快；内存是大而慢的 RAM。运算要反复读数，必须放最快的存储。

**Q4. 最简 CPU 框图？**
- 学员答：画不出。
- ✅ 基本部件：**PC、IMEM（指令内存）、Decoder（译码器）、RegFile（寄存器堆）、ALU、DMEM（数据内存）、adder** + 连接用的 MUX。

**Q5. 时钟沿到来时，寄存器是一起更新还是顺序更新？**
- 学员答：一起更新；并提到“竞争/毛刺”。方向对，但表述绕。
- ✅ **同步更新**：所有寄存器在**同一个时钟上升沿一起更新**。理由正是组合逻辑有**毛刺**，用“电平/异步”触发会出错，所以用**时钟沿统一采样**保证稳定。异步电路复杂、易错，本项目不碰。

## 第 3 轮：答案在上一轮讲过

**Q1. PC 存什么？普通指令执行完 PC 变多少？JAL 呢？**
- ✅ PC 存"**下一条指令的地址**"。
  - 普通指令：PC = **PC + 4**（每条指令 4 字节）。
  - JAL 跳转：PC = **当前 PC + 立即数**（跳到目标）。

**Q2. 指令哪几位判断类型？这个过程叫什么？**
- ✅ **最低 7 位 = opcode（instr[6:0]）**，判断指令类型（**不是**前 4/8 位）。
- 过程叫 **译码（decode）**。

**Q3. 存储层次为什么这么设计？本项目用到哪层？**
- ✅ 快-小-贵 → 慢-大-便宜，用**层次**兼顾速度与容量。
- 本项目：**寄存器堆**（+ 以后的数据内存）；**Cache 不做**。

**Q4. 为什么"时钟沿统一采样"能避免毛刺错误？**
- ✅ 组合逻辑在稳定前会有**短暂抖动（毛刺）**；用时钟沿**只在信号稳定后采样一次**，抖动被忽略，所以不会出错。

## 概念补充（并入自旧笔记）

### A. 补码与有符号范围
- **补码数值（最高位为 1 时）= 无符号值 − 2^N**
  `1010 = 10 − 16 = -6`；`1000 = 8 − 16 = -8`；`1111 = 15 − 16 = -1`
- **取反 + 1 = 求相反数**：`~x = (2^N − 1) − x`，`~x + 1 = −x`
- **N 位范围**：`-2^(N-1) ~ 2^(N-1) − 1`
  - 负数和非负数各 `2^(N-1)` 个；**正数比负数少一个**（0 占了名额）
  - 只有一个 0（`0000`）
- **32 位**：`-2^31 ~ 2^31 − 1`
- `$signed(a)` = 把这些 bit 按补码解释；不加则按无符号。

### B. `rd/rs1/rs2` 是“编号”，`wr_data` 是“数据”
```
rs1/rs2 → 读第几号寄存器
rd      → 写第几号寄存器
wr_data → 写什么数据
```
`logic [4:0] rd` 的 `[4:0]` 是**编号位宽**（32 个寄存器→5 bit）；
`logic [31:0] wr_data` 的 `[31:0]` 是**数据位宽**。
所以 `if (we && rd != 0)` 比较的是**编号**（保护 x0），不是数据。

### C. SLT 家族命名
```
SLT   = signed   + 寄存器     rd = (signed rs1 < signed rs2) ? 1 : 0
SLTI  = signed   + 立即数
SLTU  = unsigned + 寄存器
SLTIU = unsigned + 立即数
```
- `LT` = Less Than（小于）；`set` = 置位（成立置 1）。
- `I` = **Immediate（立即数）**，不是“立即执行”，和 `always_comb/ff` 无关。

### D. Verilog vs C 的思维
```
C        ：描述“按顺序执行这些语句”
Verilog  ：描述“搭一个什么电路，信号怎么连、什么时候更新”
```
详见 `06-verilog-ref.md`。

### E. 一条语句的三层表示（C → 汇编 → 机器码）
```
C        a = b + 1;
汇编     mov 0x804a01c, %eax     # 读 b
         add $0x1, %eax          # +1
         mov %eax, 0x804a018     # 写 a
机器码   a1 1c a0 04 08 / 83 c0 01 / a3 18 a0 04 08
```
- **CPU 只认机器码**；C/汇编是给人（和编译器）的。
- x86 机器码**变长**（2/3/5 字节）；**RISC-V 固定 32 位**。
- RISC-V 版近似：`lw t0,0(t1)` / `addi t0,t0,1` / `sw t0,0(t2)`。
- **定长指令**正是 RISC-V 流水线比 x86 简单的原因（取指/译码规整）。
- 这是 P4「跑 C 程序」要走的链：`C → 编译 → 汇编 → 机器码 → 塞进内存`。

### F. 字节序（Endianness）
- **大端**：高字节存低地址（网络序、人类书写习惯）。
- **小端**：低字节存低地址（**x86、RISC-V**）。
- 例：`0x12345678` 小端内存 = `78 56 34 12`。
- 硬件爱小端：从最低字节开始处理进位、类型截断零成本。
- **本项目**：RISC-V 是**小端**。
  - `addi x5,x6,10 = 0x00A30293` 存内存 = `93 A3 02 00`。
  - 塞程序进 imem / `LW` / `SW` 全按小端。
  - 别和网络字节序（大端）混。
- **为什么网络用大端**：
  - **主因是历史**：早期互联网骨干设备（IBM/Sun 等）都是大端。
  - **技术友好**：先发高位字节 → 路由器可**前缀匹配、边收边判**（早停）。
  - ⚠️ 别把"路由方便"当成唯一原因（过度归因）。
- **本质**：**大端偏"判断/语义"（前缀即分类），小端偏"计算/进位"（从最低位累加）**。
- C 里转换：`htonl/ntohl`（host↔network，32 位）、`htons/ntohs`（16 位）。

### G. 按位运算 vs 逻辑运算
- **按位**（`&` `|` `^` `~`）：对**每一位**分别套用同一个逻辑门规则，输出与输入**等宽**。
  - `b = 3'b111` → `a | b` 恒 `= 3'b111 = 7`（每位的 `1|任何=1`）。
  - `b = 0` → `a | 0 = a`。
- **逻辑**（`&&` `||` `!`）：把整个向量当成**一个布尔值**（非零=真），输出**1 位**。
- 详见 `06-verilog-ref.md` 第 9 节。

### H. 为什么组合逻辑漏赋值会产生 latch？
- **现象**：`always @(*)` 里 `case` 没写 `default`，综合警告 "inferring latch"。
- **原因**：某组输入下**没有给输出赋值** → Verilog 语义是"**保持上一次的值**" → 需要**记忆** → 组合逻辑做不到，综合器只能生成**锁存器(latch)**。
  ```systemverilog
  always @(*) case (sel)
      3'd0: out = data0;
      // 没写 default → sel=6/7 时 out 保持旧值 → latch
  endcase
  ```
- **两种避免写法**：
  1. 加 `default: out = 4'd0;`
  2. 进 `always` 先赋默认值：`out = 4'd0;` 再 `case`
- **为什么 latch 坏**：偷偷记忆、带毛刺、时序难分析、FPGA 上性能差，通常是 bug。
- 组合逻辑**必须在所有情况下都给输出赋值**。参见 `09-pitfalls.md` 第 2 条。

### I. PC（程序计数器）
- **PC = Program Counter**，一个 **32 位寄存器**，存**当前要执行指令的地址**。
- 在 **IF(取指)** 阶段：
  1. 用 PC 的地址去指令内存取指令；
  2. 算下一条 PC（通常 PC+4，跳转时是目标地址）；
  3. 时钟沿把新 PC 存回。
- **是寄存器(状态)** → 只在时钟上升沿更新（`always_ff` + `<=`），是我们后面要写的 `pc.sv`。

### J. imem 与 dmem（两种内存）
| | **imem**（指令内存） | **dmem**（数据内存） |
| --- | --- | --- |
| 存什么 | **指令**（机器码） | **数据**（变量/数组） |
| 谁访问 | CPU **取指**（IF） | `LW`/`SW`（MEM） |
| 地址来自 | **PC** | **ALU** 算的 `rs1+imm` |
| 读/写 | **只读** | **可读可写** |

- 类比：imem = 菜谱（一步步做什么）；dmem = 工作台/冰箱（原料与成品）。
- 为什么分开：用途和访问方式不同（只读 vs 读写），分开后**取指和访存可同时进行**（流水线里不打架）。
- 一句话：**imem 存指令、PC 取、只读；dmem 存数据、ALU 给地址、LW/SW 读写。**

### K. 为什么"丢低 2 位 = 除以 4"
- **二进制右移 n 位 = 除以 2ⁿ**（十进制右移一位 = 除以 10，同理）。
- **丢低 2 位 = 右移 2 位 = 除以 4**。
- 例：`addr = 12 = 1100` → 丢低两位 `00` → `0011 = 3`，而 `12 ÷ 4 = 3` ✔
- **用途**：字节地址 → 字索引。指令是 4 字节一条，所以 `mem[addr[31:2]]` 就是"第几条指令"。
- （`addr[1:0]` 恒为 00，因为 PC 4 字节对齐。）

### L. 为什么 imem 里 `addr` 要 ÷4
- `addr`(PC) 是**字节地址**:每条指令 4 字节 → PC 依次 `0,4,8,12…`
- `mem[ ]` 是**按"第几条指令"**存(每格 4 字节)
- 换算：**字节地址 ÷ 4 = 字索引**
```
PC(字节):  0   4   8   12
mem(索引): 0   1   2   3
```
- **不 ÷4 的后果**:`addr=4 → mem[4]`,跳过 mem[1..3],取错 + 浪费 3/4 空间。
- **为什么分开**：CPU 层面统一用字节地址(PC、LW/SW 都是)；内存每格存一整条指令(字) → 中间要"字节地址→字索引"。
- 宿舍类比：每人一个房号(字节)，但按"房间"找人(字，4 个房号=1 间)。找 12 号 → 12÷4 = 第 3 间。

## 第 4 轮：指令格式专题（今晚复盘）

> 这一轮是"指令编码"最抽象的部分。下面每条都反复问过、确认过。

**1. `instr` 是什么**
= 一条 **32 位机器指令**（IF 取出 → ID 译码）。`imm_gen` 就从它的某些位里解出立即数。

**2. 指令 ≠ opcode**
指令 = 整条 32 位；opcode = 其中最低 7 位。指令 ⊃ opcode。

**3. opcode / funct3 / funct7 是"层级"，不是优先级**
```
opcode[6:0]   大类
funct3[14:12] 中类
funct7[31:25] 小类（只在 funct3 分不出时才看）
```
- funct3 含义**依赖 opcode**（000 在 R 型是 ADD、I 型是 ADDI）。
- `funct7` **只有 R 型有**，因为只有它有空位（[31:25]）。

**4. opcode 按"功能"分，不是按"格式"分**
- 一种格式**可以有多个 opcode**：I 型有 3 个（0x13 运算 / 0x03 读内存 / 0x67 JALR），U 型有 2 个。
- 一个 opcode 只对应一种格式。
- **为什么 I 型没有 funct7**：立即数占了 `[31:20]`，**没位置**放 funct7。

**5. 为什么立即数位数不同 → 只剩两种：12 和 20**
| 格式 | 用掉的固定字段 | imm |
| --- | --- | --- |
| I / S / B | opcode+...+rs1/rs2+funct3 = 20 | **12** |
| U / J | opcode + rd = 12 | **20** |
一句话：**立即数宽度 = 32 − 用掉的字段位数**。

**6. 立即数为什么被拆开**
因为**寄存器/funct3 位置固定**（译码简单）→ 立即数只能填剩下的"缝"。
- I / U：缝连续 → 不拆
- S / B / J：寄存器字段插在中间 → 被切断 → 拆几段
- B / J：偏移是 2 的倍数 → 丢 bit0
- 拼法规律：**按立即数从高到低，把散落的位捡回来**

**7. 符号扩展 vs 零扩展**
```
缺低位 → 补 0      (只有 U 型)
缺高位 → 符号扩展   (I/S/B/J)
```
- 符号扩展 = 把最高位（符号位）复制到高位 → 有符号数变宽后**值不变**。
- 例：4 位 `1010(=-6)` → 8 位 `1111_1010(=-6)`。

**8. 字段 ↔ 模块的对应（谁读哪几栏）**
| 字段 | 谁读 |
| --- | --- |
| opcode | decoder（判断）＋ imm_gen（判类型） |
| rd | regfile（写地址） |
| funct3 | decoder + alu_ctrl |
| rs1 / rs2 | regfile（读） |
| funct7 | alu_ctrl（R 型） |
| imm | imm_gen 生成 |
**每个模块各读各的栏；一条指令（32位）共享给所有模块。**

**9. imm_gen 到底做了什么**
1. 从指令里**捡出立即数那几栏**（按格式切片）；
2. 扩展成 **32 位**输出（符号/零扩展）。
- 它**不碰、不管** rs1/funct3/rd（那些归别的模块）。

## 第 5 轮：分支 / 跳转 / 偏移量 / 对齐 / 压缩

**1. 分支 vs 跳转**（都改变 PC）
- **分支**：(有条件)满足才跳。例 `BEQ`、`BNE`。
- **跳转**：(无条件)必然跳。例 `JAL`、`JALR`。

**2. 偏移量（offset）**
- **目标地址 = PC + offset**。
- offset 是**相对当前 PC 跳多远**（不是绝对地址），**有符号**（可前跳/后跳）。
- 为什么用相对偏移：① 省位（±4KB/±1MB，不用存 32 位地址）② 位置无关（代码放哪都能跑）。

**3. 为什么偏移量是偶数**
- 目标地址和 PC 都是"**指令地址**"。
- 指令最少 2 字节 → 指令地址**至少是 2 的倍数（偶数）**。
- **偶数 − 偶数 = 偶数** → offset 的 **bit0 恒为 0**。

**4. 2 字节对齐 = 地址是偶数**
- "N 字节对齐" = **地址是 N 的倍数**。
  - 2 字节对齐 → 偶数地址（0,2,4,6…）
  - 4 字节对齐 → 4 的倍数（0,4,8,12…）
- 指令都放在**偶数地址**上（因为指令最少 2 字节）。

**5. 编码里的 `1'b0`（B/J 型）**
- 既然 offset 的 bit0 恒 0，就**不存它**（省 1 位）。
- 拼回来时在末尾补 `1'b0`：`{..., instr[11:8], 1'b0}`。
- 对比：I/S 型的立即数是普通数值（低位有意义），不省、也不补 0。

**6. 压缩指令（C 扩展）**
- 有些常见指令可用 **16 位（2 字节）** 表示（如 `c.addi`/`c.lw`/`c.j`），**汇编器自动选**，让代码更小。
- 硬件区分：`inst[1:0] != 11` → 16 位；`== 11` → 32 位。
- **本项目不做 C 扩展** → 所有指令都是 32 位（4 字节）。
- 但为什么编码仍按 **2 字节**粒度？因为**规范允许压缩指令**，偏移量统一按 2 字节对齐以兼容。

**7. 为什么"偶数 ⟺ bit0=0"（权重论证）**
- 各位权重：`bit0=2⁰=1`（**唯一奇数权重**），`bit1=2`、`bit2=4`、`bit3=8`…（**全是偶数**）。
- 高位贡献 = 偶数权重 × (0 或 1) = **永远是偶数**。
- 值 = (一堆偶数) + `bit0×1` → **奇偶只看 bit0**：
  - `bit0 = 0` → 偶数
  - `bit0 = 1` → 奇数
- 十进制类比：判断奇偶**只看个位**（个位权重 1，十位以上都是 10 的倍数=偶数）。

**8. B/J 的 `1'b0` 完整推导链**
```
① B/J 是跳转 → 要算偏移量 → offset = 目标地址 − PC
② 目标、PC 都是指令地址 → 都是偶数（指令长度是 2 的倍数）
③ 偶数 − 偶数 = 偶数 → offset 是偶数
④ 偶数 ⟺ bit0 = 0（bit0 是唯一奇数权重）
⑤ bit0 恒为 0 → 存它没意义 → 编码时省略
⑥ 拼回来补 1'b0 还原
```

## 第 6 轮：控制信号（lw/sw/beq/bne + src 含义）

**`src` = Source（来源）**：MUX 的"从哪条路来"选择信号。
- `alu_src`：ALU 的 B 口选谁 → `0`=rs2，`1`=imm。
- `result_src`：写回寄存器堆的数据来源 → `0`=ALU，`1`=内存，`2`=PC+4（给 JAL/JALR）。

**四条指令怎么推控制信号**：

| 指令 | reg_write | mem_read | mem_write | alu_src | alu_op | branch | result_src |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `lw x5,8(x6)` | 1 | 1 | 0 | 1 | 00 | 0 | 1 |
| `sw x5,8(x6)` | 0 | 0 | 1 | 1 | 00 | 0 | x |
| `beq x5,x6,L` | 0 | 0 | 0 | 0 | 01 | 1 | x |
| `bne x5,x6,L` | 0 | 0 | 0 | 0 | 01 | 1 | x |

**推法**（问 4 个问题）：
1. 写寄存器吗？→ `reg_write`
2. ALU 第二操作数是寄存器还是立即数？→ `alu_src`
3. 哪一大类？(访存算地址=00，分支=01，R=10，I算术=11) → `alu_op`
4. 读/写内存吗？→ `mem_read`/`mem_write`；写回来源？→ `result_src`

**规律**：
- `lw`/`sw` 都"算地址"（`alu_op=00`）；区别只在 `mem_read` vs `mem_write` + 写不写回。
## 第 7 轮：5 个阶段的两个易错点

**1. 控制信号在 ID 产生，不是 IF**
- IF 只负责**取指令**，不看内容。
- **ID 阶段**：`decoder` 读 `instr` → 产出所有控制信号。
- 控制信号要**跟着指令穿过流水线寄存器**，走到该用的那一级：
  - `alu_src` / `alu_op` → EX 用
  - `mem_read` / `mem_write` → MEM 用
  - `reg_write` / `result_src` → WB 用
- 所以 `id_ex` / `ex_mem` / `mem_wb` 里**都要存控制信号**。

**2. `lw` 的"地址"和"数据"分别在哪一级**
- **EX**：算**地址** = `rs1 + imm`。
- **MEM**：用地址**读内存** → 得到**数据（结果）**。
- 记忆：`lw` = "EX 算地址 → MEM 取数据"。**地址 ≠ 结果。**
- 对比 `addi`：不访存，结果在 **EX** 就得到了，MEM 空过。

## 第 8 轮：控制信号"随行"穿过流水线

**问题**：控制信号(ID 产生)EX 不用，但 MEM/WB 要用——怎么到那儿？

**答**：**控制信号像"行李"，跟着指令一级一级传下去**；每级"用掉自用的、其余原样转发"。

```
ID 产生 8 个控制信号
   ↓ 存 id_ex
EX  用 alu_src / alu_op
    其余 → ex_mem
MEM 用 mem_read / mem_write
    其余 → mem_wb
WB  用 reg_write / result_src
```

- **每一级流水线寄存器都同时存"数据 + 控制信号"。**
- EX 不"产生"控制信号，只是**让它们路过**（EX 自己产出的只有 `alu_result` / `zero`）。

**各寄存器"存什么"的通用规则**：
> 存"这一级的产出" + "后面各级要用、但还没用到的控制信号"。
> 简化记法：**`id_ex` ≈ 把 ID 的全部产出都存下**；之后每级用掉该用的、其余转发。

## 五阶段速览表（配合 01-architecture §7）

| 阶段 | 输入 | 处理 | 模块 | 输出 |
| --- | --- | --- | --- | --- |
| **IF** 取指 | `pc` | 取指令、算 pc+4 | pc, imem, adder | `instr`, `pc`, `pc+4` |
| **ID** 译码 | `instr` | 解控制、读寄存器、生成 imm | decoder, regfile(读), imm_gen | `rs1_data`, `rs2_data`, `imm`, `rd`, 控制, funct3/7 |
| **EX** 执行 | `rs1/rs2_data`, `imm`, 控制 | 选第二操作数、ALU 运算 | alu_ctrl, ALUSrc mux, alu | `alu_result`, `zero` |
| **MEM** 访存 | `alu_result`(地址), `rs2_data`, 控制 | LW 读 / SW 写，其它空过 | dmem | `mem_rdata` |
| **WB** 写回 | `alu_result` 或 `mem_rdata`, `rd`, 控制 | 选结果写回 regfile | WB mux, regfile(写) | 寄存器更新 |

**一句话**：IF 拿指令 → ID 看懂+备料 → EX 算 → MEM 存取内存 → WB 写回。

**单周期 vs 流水线**：单周期 5 步在**同一周期内连着发生**；流水线在 `IF|ID`、`ID|EX`、`EX|MEM`、`MEM|WB` 这 4 个边界**各插一个寄存器**，"半成品"存一拍，于是不同指令同拍待在**不同阶段**。

**流水线"翻译规则"**：每个模块的输入，来自**它所在段的前一个流水线寄存器**的输出（IF 例外，来自 PC）。

## 第 7 轮：Decoder 控制信号推导口诀与表格

针对 `worksheet-decoder.md` / `worksheet-decoder.xlsx` 中的每一列信号推导逻辑：

### 1. 信号含义与“灵魂拷问”

| 信号名称 | 硬件问题 | 值为 1 的场景 | 值为 0 的场景 |
| :--- | :--- | :--- | :--- |
| **`reg_write`** | 这条指令需要写通用寄存器（rd）吗？ | 算出结果要存寄存器（add, addi, lw, lui, jal等） | 不需要存寄存器（sw 仅写内存，beq/bne 仅跳转） |
| **`mem_read`** | 需要从数据内存（Data Memory）读数据吗？ | 仅 Load 指令（如 `lw`）为 1 | 其余指令全为 0 |
| **`mem_write`** | 需要向数据内存写数据吗？ | 仅 Store 指令（如 `sw`）为 1 | 其余指令全为 0 |
| **`alu_src`** | ALU 的第二操作数（B口）选谁？ | 带立即数的指令（I型算术、lw、sw）选立即数（=1） | 寄存器间运算（R型）、分支比较（B型）选 rs2（=0） |
| **`branch`** | 是条件分支指令吗？ | 仅分支指令（`beq`, `bne`）为 1 | 其余指令全为 0 |
| **`result_src`** | 写回寄存器堆的数据来源是谁？ | `0` = ALU 计算结果<br>`1` = 内存读出的数据（`lw`）<br>`2` = PC + 4（跳转链接） | 不写回寄存器时填 0 或 x（无关项） |
| **`alu_op`** | ALU 进行哪一大类运算？ | `00` = 访存求地址（加法）<br>`01` = 分支（减法比较）<br>`10` = R型运算（看 funct3/funct7）<br>`11` = I型算术运算（看 funct3） | jump 核心版恒为 00 |

### 2. 常见指令类型速查归类
- **R 型（add, sub, and, or, xor, slt）**：`reg_write=1`, `mem_read=0`, `mem_write=0`, `alu_src=0`, `alu_op=10`, `branch=0`, `result_src=0`
- **I 型算术（addi, andi, ori, xori, slti）**：与 R 型仅差 `alu_src=1`, `alu_op=11`
- **Load（lw）**：`reg_write=1`, `mem_read=1`, `mem_write=0`, `alu_src=1`, `alu_op=00`, `branch=0`, `result_src=1`
- **Store（sw）**：`reg_write=0`, `mem_read=0`, `mem_write=1`, `alu_src=1`, `alu_op=00`, `branch=0`, `result_src=x(0)`
- **Branch（beq, bne）**：`reg_write=0`, `mem_read=0`, `mem_write=0`, `alu_src=0`, `alu_op=01`, `branch=1`, `result_src=x(0)`

## 第 8 轮：为什么先有 pc_next 才有 pc？（组合与时序的因果）

在计算机体系结构（如 CPU 的流水线/单周期设计）中，程序计数器（PC，Program Counter）的更新逻辑决定了“为什么先有 pc_next 才有 pc”。

### 核心理解
**`pc_next` 是输入的“下一个目标地址”，而 `pc` 是当前时刻寄存器里锁存的“当前地址”。**  
必须先计算出下一步要去哪里（`pc_next`），时钟上升沿到来时，硬件才能把这个值真正存进寄存器变成当前的 `pc`。

### 核心逻辑因果关系
1. **组合逻辑实时计算 `pc_next`**：  
   在每一个时钟周期里，上一级的逻辑（比如加法器 `pc + 4` 或者分支/跳转指令计算出的目标地址）通过组合逻辑实时计算出下一条指令应该是什么，这个值作为准备好的输入，就是 `pc_next`。
2. **时钟沿触发更新 `pc`**：  
   `pc` 是一个时序逻辑寄存器（D 触发器）。只有当时钟上升沿（`posedge clk`）到来时，寄存器才会把输入端（`pc_next`）的数值采样存进来，更新输出端的 `pc`。

> **结论**：  
> 在时间顺序上是：**先由组合逻辑得出 `pc_next` 的数值，等待时钟沿触发，最后才把这个值锁存给 `pc`。**
