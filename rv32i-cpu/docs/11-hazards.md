## 0. 这一阶段要解决什么

流水线把一条指令的五个步骤拆到五拍，同时跑五条指令。
代价是：**后面的指令会用到前面还没算完的结果**。

| 冒险类型 | 起因 | 阶段 | 状态 |
| --- | --- | --- | --- |
| 数据冒险 RAW | 后一条要读的寄存器，前一条还没写回 | 6a 复现 / 6b 转发 / 6c 停顿 | 6b ✅，6c ✅ |
| 控制冒险 | 分支跳不跳要到 EX 才知道，此时已取错指令 | 6d 冲刷 | 6d ✅（分支；JAL/JALR 未做） |
| 结构冒险 | 两条指令同一拍抢同一个硬件 | —— | 本设计不存在 |

**结构冒险为什么不存在**：指令内存和数据内存是分开的两套（哈佛结构），
寄存器堆有 2 个读口 + 1 个写口，刚好够五级各用各的。

---

## 1. 数据冒险只有 RAW 一类

这是最先要建立的概念，它能砍掉一大半无效思考。

三个名词：

| 名字 | 含义 | 本设计里会发生吗 |
| --- | --- | --- |
| RAW | Read After Write，后读先写的结果 | ✅ 会，主要矛盾 |
| WAR | Write After Read，后写覆盖先读 | ❌ 不会 |
| WAW | Write After Write，后写覆盖先写 | ❌ 不会 |

**为什么 WAR / WAW 不会发生**：

- 所有**读**都发生在 ID 级
- 所有**写**都发生在 WB 级
- 单发射、顺序执行，指令按程序顺序流过五级

于是对任意两条指令 I1 在前、I2 在后：
I2 的读（ID）一定早于 I1 的写（WB），所以不存在"写覆盖了别人还没读的值"；
I2 的写也一定晚于 I1 的写，"后来的覆盖先前的"本就是正确的语义。

> 只有引入乱序执行或多发射时，WAR / WAW 才会出现。现在不用管。

## 2. 工具：时空图怎么读

判断有没有冒险，只看一张表：横轴周期，纵轴指令，格子里是阶段。

```
         C1   C2   C3   C4   C5
I1       IF   ID   EX   MEM  WB
I2            IF   ID   EX   MEM  WB
I3                 IF   ID   EX   MEM  WB
```

读法：
1. 找到"要用某个寄存器"的指令，看它在 **EX** 是哪一拍
2. 找到"产生这个寄存器"的指令，看它那一拍在哪一级
3. 按下一节的表判断值在哪

**关键**：判断"值在哪"，要看**产生它的指令当下处于哪一级**，而不是看它什么时候"写回"。

## 3. 阶段6a：先把冒险看见

单周期跑同一段程序是对的，换成流水线就错。这一步的价值是**证明问题真实存在**，
而不是听别人说有就有。

测试程序（`imem` 早期版本）：

```
addi x1, x0, 5      x1 = 5
add  x2, x1, x1     期望 10，实际 0
```

现象：`x2 = 0`。原因：`add` 在 ID 级读 x1 时，`addi` 还在 EX，x1 仍是 0。

## 4. 阶段6b：转发（已完成）

### 4.1 两条近路

| 相关距离 | 前一条此刻在 | 值在哪 | 走哪条 |
| --- | --- | --- | --- |
| 隔 1 条 | MEM | EX/MEM | EX/MEM 转发 |
| 隔 2 条 | WB | MEM/WB | MEM/WB 转发 |
| 隔 3 条 | 已写回 | 寄存器堆 | 无需转发 |

**为什么隔 3 条也可能要转发**：`regfile` 的写是 `always_ff @(posedge clk)`，
写入发生在**时钟沿**。WB 那一拍期间 `regs[rd]` 还是旧值。
所以"WB 级正在执行" ≠ "寄存器堆已经更新"。

### 4.2 三个条件（缺一不可）

```
reg_write && (rd != 0) && (rd == rs)
```

| 条件 | 漏了会怎样 |
| --- | --- |
| `reg_write` | `sw x1, 4(x2)` 的 `instr[11:7]` 是立即数低 5 位（=4），看着像写 x4，会把**地址**转发出去 |
| `rd != 0` | `addi x0, x0, 5` 能算出 5，转发后 x0 不再是 0 |
| `rd == rs` | 没命中，无意义 |

### 4.3 优先级：EX/MEM > MEM/WB

```
I1  add x1, x2, x3
I2  add x1, x4, x5     ← 也写 x1
I3  add x6, x1, x7     ← 用 x1
```

I3 在 EX 时，I1 在 WB、I2 在 MEM，两条通路都命中。
**取 EX/MEM**，因为 I2 更年轻，它的结果才是最终生效值。

写法上用 `if / else if`，顺序即优先级；用两个独立 `if` 会变成后者覆盖前者，优先级反掉。

### 4.4 三个转发入口

| 入口 | 用哪个信号 | 备注 |
| --- | --- | --- |
| ALU 的 A 口 | `forward_a` | |
| ALU 的 B 口 | `forward_b` | **MUX 必须在 ALUSrc 之前** |
| `sw` 的存数据 | `forward_b` | 两者来源都是 rs2，可共用 |

B 口顺序反了，`addi`/`lw` 这类用立即数的指令也会被"转发"，
等于把无关指令的 ALU 结果当成立即数。

### 4.5 实现位置

```
id_ex 补 rs1 / rs2 编号   →  forward_unit 比较用
forward_unit.sv           →  只输出选择信号，不搬数据
cpu_pipe 的 EX 段         →  两个 MUX 按选择信号取值
```

**为什么 `id_ex` 要专门存编号**：ID 级读出来的是"数据"，可能是旧值；
转发要判断的是"编号是否相同"，光有数据比不了。

## 5. 阶段6c：load-use 停顿（已完成）

### 5.1 转发救不了的那一种

```
lw  x1, 0(x2)
add x3, x1, x4
```

|    | C1 | C2 | C3 | C4  | C5 |
| -- | -- | -- | -- | --- | -- |
| lw | IF | ID | EX | MEM | WB |
| add |   | IF | ID | EX  | MEM |

`add` 在 C4 进 EX，需要 x1。看三个候选：

| 候选 | C4 时里面是什么 |
| --- | --- |
| EX/MEM | lw 的 ALU 结果 = 访存**地址**，不是数据 |
| MEM/WB | 更早指令留下的东西，lw 的数据还没到 |
| 寄存器堆 | 旧 x1，写回要等 C5 末的时钟沿 |

**三个地方都没有**。转发是"抄近路"，前提是值已经被造出来；这里值还没造出来。

### 5.2 停一拍之后

|    | C1 | C2 | C3 | C4  | C5  | C6 |
| -- | -- | -- | -- | --- | --- | -- |
| lw | IF | ID | EX | MEM | WB  |    |
| add |   | IF | ID | ID  | EX  | MEM |
|      |    |    | 检测 | 停住 | 这时转发可用 | |

到 C5，add 才进 EX；lw 在 WB，数据已锁进 MEM/WB，转发生效。
**6c 只负责"等一拍"，送数据仍然是 6b 的转发作。**

### 5.3 三处改动

| 模块 | 现在 | 要改成 |
| --- | --- | --- |
| `program_counter` | 每拍无条件更新 | 加 `stall`：停住时不更新 |
| `if_id` | 每拍无条件前进 | 加 `stall`：保持，让指令留在 ID |
| `id_ex` | 每拍无条件前进 | 加 `flush`：清空控制信号，灌一个气泡进 EX |

第三处最易漏：光让 PC 和前两级停住不够，还要保证 EX 这一拍**什么都不做**。
往 `id_ex` 塞全 0 的假指令，它走到 WB 时 `reg_write=0`、`mem_write=0`，不会破坏状态。

### 5.4 检测条件

在 ID 级判断（lw 在 `id_ex` 里，下游指令还在 `if_id` 里）：

```
id_ex_mem_read && (id_ex_rd != 0)
                && (id_ex_rd == if_id_instr[19:15] || id_ex_rd == if_id_instr[24:20])
```

| 项 | 为什么 |
| --- | --- |
| `mem_read` | 只有 lw 的数据晚到；ALU 结果 C3 就在 EX/MEM 了 |
| `rd != 0` | x0 不算相关 |
| 用 `if_id_instr` 而非 `id_ex_rs1` | 要判断的是**还没进 EX 的那条** |

### 5.5 误停问题与修法（已修）

`addi x3, x0, 5` 的 `instr[24:20]` 是立即数低 5 位，不是 rs2。
若前一条正好是 `lw x5, ...`，`id_ex_rd == 5` 会误命中，白停一拍。

**影响**：不算功能 bug——结果仍然正确，只是多花一个周期。

**修法**：让 `decoder` 额外输出 `uses_rs1` / `uses_rs2`，检测时只有**真正读的源**才参与比较。

| 指令 | uses_rs1 | uses_rs2 |
| --- | --- | --- |
| R 型 | 1 | 1 |
| I 型算术 | 1 | 0 |
| lw | 1 | 0 |
| sw | 1 | 1 |
| 分支 | 1 | 1 |

**验证方法**：testbench 里数 `stall` 被拉高的次数。
程序安排一对真相关 + 一对假相关，正确设计应恰好停 1 拍。
去掉 `uses_*` 条件重跑会变成 2 拍——说明这个测试确实抓得住。

### 5.6 实现位置

| 文件 | 改动 |
| --- | --- |
| `decoder.sv` | 新增输出 `uses_rs1` / `uses_rs2` |
| `hazard_unit.sv` | 新建，输出 `stall` |
| `program_counter.sv` | 加 `stall` 输入，停住时不更新 |
| `if_id.sv` | 加 `stall` 输入，保持原值 |
| `id_ex.sv` | 加 `flush` 输入，清空 = 灌气泡 |

⚠ 接口一改，所有例化点都要跟着接。
`cpu_top` 是单周期，不需要停顿，但 `program_counter` 的 `stall` 必须显式接 `1'b0`——
悬空是 Z，`!Z` 变成 X，PC 会直接卡死。

## 6. 阶段6d：控制冒险（分支已完成，跳转未做）

### 6.1 问题

分支要不要跳，要到 EX 级 ALU 算出 `zero` 才知道。
可那时 PC 已经往前取了两条指令——它们可能是错的，必须丢掉。

```
         C1   C2   C3   C4   C5
beq      IF   ID   EX   MEM  WB
I+1           IF   ID   ✗   ✗     ← 取错了，要丢
I+2                IF   ✗   ✗     ← 取错了，要丢
```

### 6.2 三个决策

| 问题 | 选择 | 理由 |
| --- | --- | --- |
| 在哪一级判断？ | **EX** | ALU 已经算好 `zero`，直接复用；在 ID 判断要额外加比较器和转发 |
| 冲刷哪几级？ | `if_id` + `id_ex` | 把 ID 级和正在取的那条都变成气泡 |
| 目标地址怎么算？ | `id_ex_pc + id_ex_imm` | ★ 必须用**分支自己的 PC**，不能用当前 `pc` |

**为什么不能用当前 `pc`**：分支进 EX 时，`pc` 已经指向它后面第 2 条了。
用当前 `pc` 算出来的目标会偏移 8 字节，跳飞。

### 6.3 beq / bne 的判断

ALU 对分支做减法，`zero=1` 表示两数相等。再按 funct3 决定方向：

| funct3 | 指令 | 跳的条件 |
| --- | --- | --- |
| 000 | beq | `zero` |
| 001 | bne | `~zero` |
| 其它 | 未实现 | 不跳 |

### 6.4 代价

冲刷两级 = 每次跳转**罚 2 拍**。
（如果改成在 ID 级判断，只需冲刷一级，罚 1 拍——但要多一个比较器和额外的转发通路。）

### 6.5 实现位置

| 文件 | 改动 |
| --- | --- |
| `cpu_pipe.sv` | 算 `branch_target` / `branch_taken` / `pc_redirect`；`next_pc` 改成 MUX |
| `if_id.sv` | 加 `flush`，优先级高于 `stall` |
| `id_ex.sv` | 复用已有 `flush`，接 `stall \| pc_redirect` |

### 6.6 验证

程序里放两条**毒药指令**（`addi x11, x0, 111` / `222`），被分支跳过：

- `beq x1, x1, +8` → 相等，跳过第一条毒药
- `bne x1, x2, +8` → 5≠10，跳过第二条毒药
- `bne x1, x1, +8` → 相等，**不该**跳

判定：
- `x11` 必须是 3（两条毒药都没执行）
- `x12` 必须是 2（最后一条 bne 没跳）
- `pc_redirect` 拉高次数必须**恰好 2**

把 `flush` 断掉重跑，`x11` 会变成 222、跳转次数变成 3——说明测试抓得住。

### 6.7 还没做的：JAL / JALR

- `decoder` 还没实现这两条 opcode（`jump` 恒为 0）
- WB MUX 只判 `result_src[0]`，`result_src=2`（PC+4 写回）不生效
- 接的时候：`pc_redirect = branch_taken | jump_taken`，目标地址再进 MUX

## 7. 每个阶段怎么验证

| 阶段 | 测试方法 | 判定 |
| --- | --- | --- |
| 6a | 跑相关程序 | 结果错（x2=0），证明问题存在 |
| 6b | 8 条指令覆盖四种相关 | 7 个寄存器全部正确 |
| 6c | lw 后紧跟使用它的指令 + 一对假相关做对照 | 结果正确 + `stall` 恰好 1 次 |
| 6d | 分支跳 / 不跳，中间夹毒药指令做对照 | 毒药未执行 + `pc_redirect` 恰好 2 次 |

**额外手段**：单周期 `cpu_tb` 和流水线 `cpu_pipe_tb` 跑同一份程序、比同一份结果，
是一个免费的等价性检查。
