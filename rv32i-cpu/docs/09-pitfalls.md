# 09 · 避坑清单（bug 可能性）

> 平时遇到的坑，按"现象 / 原因 / 防范 / 验证"记下来。越攒越值钱。

---

## 1. 隐式网络（implicit nets）→ 高位被截断
- **现象**：编译不报错，但结果错（如 `c` 变成 `3'b001`）。
- **原因**：没声明的信号被 Verilog **偷偷当成 1-bit wire**。
  ```systemverilog
  wire [2:0] a, c;
  assign a = 3'b101;
  assign b = a;   // b 没声明 → 1-bit，b = 1
  assign c = b;   // c = 001 ← bug
  ```
- **防范**：所有信号显式声明；可选文件顶部 `` `default_nettype none ``（恢复用 `` `default_nettype wire ``）。
- **验证**：位宽不匹配时若"编译通过但值不对"，先查信号是否漏声明 / 宽度是否一致。

---

## 2. 组合逻辑漏赋值 → 综合出锁存器（latch）
- **现象**：`always_comb` / `case` / `if` 里某个分支没给输出赋值，综合警告 "inferring latch"。
- **原因**：硬件不知道"其它情况"该怎么办 → 默认"保持原值" → 需要记忆 → 变成 latch。组合逻辑不该记忆。
- **防范**：`case` 写 `default`；`if` 补 `else`；或**进 always 先给所有输出赋默认值**。
- **验证**：看综合/编译警告里有没有 "latch"。

---

## 3. `=`（阻塞）与 `<=`（非阻塞）混用
- **现象**：仿真结果诡异，和预期差一拍。
- **原因**：`=` 立即生效、`<=` 时刻末统一更新；混用破坏"同时更新"语义。
- **防范**：**组合用 `=`，时序用 `<=`**。
- **验证**：同一 always 块里是否两种赋值混着写；时序块里是否误用 `=`。

---

## 4. 位宽不匹配 → 截断 / 补零
- **现象**：值莫名变 0 或变小。
- **原因**：窄的赋给宽的补零，宽的赋给窄的截断，且不一定报错。
- **防范**：注意每根信号的位宽；拼接 `{}`、复制 `{n{}}` 明确宽度。
- **验证**：`-Wall` 打开位宽警告。

---

## 5. 老式敏感列表漏信号
- **现象**：仿真和硬件不一致（硬件对、仿真错）。
- **原因**：`always @(a)` 漏了 `b` → 仿真时 `b` 变不会重算；综合按 `@(*)` 处理。
- **防范**：组合逻辑用 `always_comb`（或 `always @(*)`），别手写信号列表。
- **验证**：检查 always 敏感列表是否手写且可能漏项。

---

## 6. testbench 在时钟沿驱动信号 → 竞争
- **现象**：仿真写入时序偶发不对。
- **原因**：在 `posedge` 同时改输入，和 DUT 采样打架，结果不确定。
- **防范**：testbench 在 **`negedge`** 驱动信号，让它在下一个 `posedge` 前稳定。
- **验证**：看 testbench 是否用 `@(negedge clk)` 驱动。

---

## 7. 字节序混淆（大端 / 小端）
- **现象**：从内存读出的值"看起来颠倒了"，或程序/数据加载后全错。
- **原因**：RISC-V 是**小端**；若按大端手工摆字节，数据全错。
- **防范**：记住 **RISC-V 小端**；`0x00A30293` 存内存 = `93 A3 02 00`。别和网络序（大端）混。
- **验证**：检查指令/数据在内存里的字节顺序；`LW`/`SW` 是否按小端。

---

## 8. 同一信号被多处驱动（multiple drivers）
- **现象**：编译报错 `not a valid l-value` / 多处驱动，或综合结果不确定。
- **原因**：一个信号被多条 `assign` 驱动（或部分位 + 整体同时驱动）。
  ```systemverilog
  assign out[2:0] = a;
  assign out[5:3] = b;
  assign out = c;      // ← 又驱动了整个 out，冲突！
  ```
- **防范**：一个信号**只有一种驱动方式**：要么整体 `assign out = ...`，要么逐段 `assign out[i] = ...`，别混。
- **验证**：搜同一信号是否出现在多个 `assign`/always 的左边。

---

## 9. 部分选择漏驱动 → 未驱动位是 `Z`（不是 latch）
- **现象**：只给向量一部分位赋值，其余位在仿真里是 `Z`，综合警告。
- **原因**：`assign out[15:0] = ...` 只驱动低 16 位，`out[23:16]` 没人驱动。
- **区分**：`assign` 漏驱动 → **高阻 Z**（+综合警告）；**latch 只出现在 `always` 组合块漏赋值**，两者不同。
- **防范**：想清楚是整体赋值还是分段；整体赋值时注意"窄赋宽会自动补 0"。
- **验证**：看仿真波形的 `Z`，或看综合警告。

---

## 10. PowerShell 改 UTF-8 文件 → 中文乱码
- **现象**：用 `Get-Content -Raw | Set-Content` 改带中文的文件后，中文变成乱码。
- **原因**：Windows PowerShell 5.1 的默认编码**不是 UTF-8**（是系统 ANSI），读写 UTF-8 文件会损坏多字节字符。
- **防范**：改带中文的文件，用**编辑器**，或明确指定 `-Encoding utf8`（且读取也要 `-Encoding utf8`）；不确定就别用脚本批量替换。
- **验证**：用 Python `open(path,'rb').read().decode('utf-8')` 检查是否合法。
